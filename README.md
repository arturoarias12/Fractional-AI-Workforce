# Fractional AI Workforce

Implementation-ready placeholder scaffold for the planned multi-agent
investment-research system.

The repository currently defines architecture, typed contracts, role
boundaries, shared-service interfaces, Agent Cards, and graph state/routing
shapes. It deliberately does **not** implement agents, real or fake market
data, a backtesting engine, an LLM adapter, LangGraph assembly, persistence, or
tests.

## Planned loop

```text
Portfolio Manager
    → {Technical Trader, Fundamental Trader, Quant Trader in parallel}
    → collective Risk / Skeptic review
    → Reporting
    → Portfolio Manager decision
    → external Memory
    → context for a later research round
```

Every hired trader receives the same normalized PM mandate, requests its own
point-in-time evidence, dynamically proposes a specialty-aligned codeable
candidate, calls the same deterministic Backtest Engine, interprets only the
returned metrics, and emits a common `TraderStrategyPackage`.

There is no active Theory Agent, Data Agent, Hypothesis Agent, central synthesis
stage, Backtest Agent, or automatic strategy-combination stage.

## Roles

Five specialists are hireable:

- Technical Trader Agent
- Fundamental Trader Agent
- Quant Trader Agent
- Risk / Skeptic Agent
- Reporting Agent

The Portfolio Manager is the human management boundary and is not hireable.
`DataService`, `BacktestEngine`, and `MemoryStore` are shared services/tools,
not agents.

## Placeholder versus implementation

| Area | Present now | Still pending |
|---|---|---|
| Agent Cards | Current roster and capabilities | Final owners and registry integration |
| Trader interfaces | Common structural Protocol | Teammate implementations and adapters |
| PM boundary | Human gateway Protocol | UI/application implementation |
| Data | Point-in-time `DataService` Protocol | Provider, payload, provenance implementation |
| Backtest | Deterministic `BacktestEngine` Protocol | Executable engine and final rule schema |
| Memory | `MemoryStore` Protocol | Persistence and retrieval implementation |
| Research contracts | Version-zero dataclasses | Cross-team field confirmation/versioning |
| Graph | Tooling ADR, state, node IDs, routing, declarative blueprint | Owner-built production LangGraph application |
| Telemetry | Correlated event contract | Storage and dashboard pipeline |

The separately developed Technical Trader currently lives under
`../project_agents/technical_trader_agent`. This scaffold points to its future
integration boundary but does not duplicate or import that development package.

Arturo's LangGraph tooling decision is recorded in
[ADR 0001](docs/adr/0001-langgraph-tooling.md). The Technical Trader package
contains an optional one-node LangGraph adapter; the production workflow,
parallel reducers, A2A lifecycle, and persistence remain with their assigned
owners.

## Implementation rules

- Strategies are dynamically generated by each trader, not hard-coded here.
- Backtest results come from deterministic code, never an LLM.
- One trader failure must not fail the whole research round.
- Risk receives the settled candidate batch, including excluded failures.
- Reporting documents only Risk survivors and does not combine strategies.
- Multiple survivors require PM selection.
- Memory is external round-to-round context, not a hireable agent.
- Shared schemas remain provisional and should evolve through adapters or
  versioned contracts.
